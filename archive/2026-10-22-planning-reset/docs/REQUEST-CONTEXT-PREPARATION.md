# 请求上下文准备

在模型目录与请求策略整理之后，将生成前的消息组装从 `ChatController` 中抽出。此次保持请求内容、插入顺序和裁剪规则，未改变配置、存储格式或页面操作。

## 职责边界

- `RequestContextBuilder` 接收本轮会话与已读取资料，选择活动分支、转换附件、组装提示词，最后调用 `ContextWindowManager` 裁剪。返回请求消息、预算报告、超限标记、正文任务标记和世界书命中记录，不读取 Riverpod 或数据库，不修改会话。
- `ClientToolPrompt` 根据本轮已选工具及传入日期生成工具提示词，不选择或执行工具。
- `StudyRequestContext` 从已加载的学习库生成导师上下文，保留旧版 `authorNote` 会话兼容与课程摘要长度限制。
- `generation.dart` 保留资料读取、技能路由、取消检查、界面状态更新和请求启动。项目资料与记忆的读取时机沿用原有流程，组装器不会再查询当前选中的会话。
- `LlmRequestPolicy` 继续决定模型、思考强度和工具轮次权限；流接收、工具执行与持久化仍由现有执行流程负责。

## 消息顺序

所有空白来源以原有的空字符串检查规则跳过，之后统一执行上下文预算管理。

普通聊天与学习：

1. 项目资料。
2. 工具提示、预识图说明、图片提示。
3. 聊天技能提示或默认提示（学习模式不使用聊天预设）。
4. 记忆；学习模式随后加入导师提示。
5. 活动分支历史，排除本轮待生成的助手消息；搜索资料插在历史最后一条消息之前。
6. 如为恢复回答，追加已有结果整理指令。

故事与多角色会话：

1. 项目资料。
2. `StoryPromptAssembler` 原有稳定前缀。
3. 记忆、图片提示、预识图说明、工具提示。
4. 活动分支历史及搜索资料；多角色会话保留助手发言的说话人标签。
5. 故事本轮动作提示。
6. 如为恢复回答，追加已有结果整理指令。

历史思考草稿保持不进入后续请求。文本附件继续展开，图片根据原生视觉能力与识图工具可用性转换。裁剪只作用于请求副本，不删除存储中的历史或修改剧情游标。

## 验证与后续边界

`request_context_builder_test.dart` 验证聊天、学习、故事和多角色的消息顺序、搜索位置、分支隔离、附件、预算超限及源会话不变。现有项目、故事、工具任务和页面测试覆盖控制器接入。

模型订阅的完成、取消和失败处理已进一步独立，见[生成流的生命周期](GENERATION-STREAM-LIFECYCLE.md)。内容累计和显示节奏见[流式答复累计与刷新](STREAM-ANSWER-PRESENTATION.md)。
