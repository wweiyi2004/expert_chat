# 搜索与网页读取工具执行

将模型触发的 `web_search`、`fetch_url` 参数处理、执行和引用合并移入 `SearchToolExecutor`。普通调用和已保存步骤的重试共用此入口。

## 职责边界

- `SearchToolExecutor` 接收工具调用、本轮参数与已有引用快照。解析模型参数，验证网页读取授权，获取既有 `ToolEngine`，返回工具文本、完整引用列表、引用变更标记及可显示的原始异常。
- `ToolEngine` 保持搜索缓存、结果过滤、正文裁剪、引用编号及搜索上下文格式，未重新实现这些规则。
- 控制器通过活动回调更新指定会话，应用返回的引用和会话错误。工具预算、停止后的跳过、工具结果保存、失败步骤重试和最终答复继续沿用原流程。
- 服务通过注入的工厂获取已有引擎，不依赖 Riverpod、设置控制器或数据库。工厂调用仍在异常处理范围内，并复用原有引擎池。

## 保持的行为

1. 搜索参数为空或 JSON 无效时，使用归一化后的本轮用户问题；有效搜索词仍使用原有归一化函数。
2. 搜索从已有引用数量加一开始编号，排除此前引用的 URL。网页读取保持原有行为，重复读取也会追加引用，不在此阶段改成去重。
3. `fetch_url` 只读取用户本轮提供的 HTTP(S) 链接。正常生成和重试使用同一个 `fetchUrlKey` 比较函数，保留主机名、路径和片段的原有规范化规则。
4. 无效或未授权 URL 在创建引擎之前返回拒绝文本，生成同一活动 ID 的开始及失败记录，不额外设置会话错误。
5. 官方联网模式下，单独网页读取继续使用客户端 DuckDuckGo 引擎。搜索模式选择和 API Key 传递保持原样。
6. 取消返回原有的取消文本，不附带需展示的异常；普通失败返回原有失败文本及原始异常，由控制器生成限定于对应会话的错误提示。

生成前的预搜索、用户链接预读取仍通过现有 `ToolEngine` 流程处理。本阶段没有迁移生图、识图、文档或 MCP 工具，也没有调整网络访问策略。

## 验证

`search_tool_executor_test.dart` 覆盖跨轮引用编号、已有来源排除、输入快照不变、参数回退、链接拒绝及活动记录、授权链接读取、后端选择、失败后重试和取消。

原有页面和任务执行测试继续覆盖工具暴露规则、实际工具协议回复、引用展示、工具预算、结果保存与失败步骤重试。测试使用替代搜索服务，不发起远端搜索请求。
