# 模块地图：职责、归属与现状

> 本文保留现有职责定位与增量方案参考。整体重构的当前目标以 [V2 架构](V2-ARCHITECTURE.md) 和 [V2 实施计划](../plans/AGENT-V2-REBUILD.md) 为准，不同时执行两份目录迁移方案。

本文件定义模块级职责。类、函数和文件拆分属于后续实现选择；模块是否独立，应由数据所有权、调用边界与验收能力判断。

状态含义：**现有**表示有对应实现；**部分**表示能力已有但边界尚未形成；**待建**表示没有可交付实现；**兼容/实验**表示沿用既有支持范围。完整路径定位与依赖 ID 见 [module-catalog.json](module-catalog.json)。

## 一、产品工作区

| ID / 模块 | 职责与拥有的数据 | 对外协作 | 当前定位 / 状态 |
| --- | --- | --- | --- |
| `app` 应用装配 | 启动、导航、主题、功能入口与依赖装配；不拥有任务执行规则 | 组装模块并提供平台服务 | `lib/main.dart`、`core/`、`features/shell/`；现有 |
| `conversation` 会话 | 消息树、分支、会话草稿、对话历史、呈现与导出 | 提交任务输入快照；将事件投影为回复 | `features/chat/`、`state/chat*`、`domain/chat/` 中的会话逻辑；部分 |
| `workspace` 工作资料 | 项目、素材、长期记忆和生成资产历史 | 提供资料快照、项目范围及产物登记 | `features/projects/`、`library/`、`memory/` 及对应仓库；现有 |
| `learning` 学习 | 导师、课程、刷题、错题、复习、学习计划、实际作答反馈 | 通过模型或任务接口请求内容；以学习记录保存结果 | `features/study/`、`domain/study/`、两个学习控制器；现有 |
| `creation` 创作 | 角色、世界信息、故事状态、创作设定 | 提供创作任务上下文与角色/世界信息贡献 | `features/story/`、`domain/story/`、角色/世界信息仓库；现有 |
| `research` 科研终端 | SSH 终端工作区、tmux、SFTP 文件视图、传输、命令提议 | 使用 SSH/SFTP 适配能力；可显式转交电脑任务 | `features/research/`、`domain/research/`、科研控制器；现有 |
| `settings` 设置 | 各模块配置的编辑入口、校验与保存协调 | 消费模块提供的配置接口；不成为业务能力总入口 | `features/settings/`、`settings_controller.dart` 与配置聚合；部分 |
| `task_workspace` 任务中心 | 查看本机/电脑任务、步骤、待确认动作、产物、停止与重连 | 仅消费任务 API 和事件 | 当前会话里有步骤与恢复 UI，独立任务中心待建 |

`workspace` 内保持 `projects`、`library`、`memory` 三个清晰子域：项目拥有关联关系，资料库拥有资产元数据和字节引用，记忆拥有记忆文档及审核状态。归入同一个工作资料模块不等于合并所有数据表或强制自动同步。

## 二、执行与连接

| ID / 模块 | 负责什么 | 不承担什么 | 现状 |
| --- | --- | --- | --- |
| `agent_runtime` 本机任务运行 | 任务状态、模型/工具轮次、预算、取消、动作前后核验、事件和恢复决策 | Widget、学习/故事实体规则、直接访问 Android API | 已有 `GenerationExecution` 等组件，整体编排仍在聊天控制器；部分 |
| `tool_registry` 工具注册与分发 | 工具描述、能力选择、执行器路由、结果归一、动作确认接口 | 具体搜索算法、SSH 会话、文档实现 | `state/chat/tools.dart`、`tool_call_runner`、`McpHostTools` 分散承担；部分 |
| `android_executor` 手机执行器 | 读取可访问界面、截图来源、点击、输入、滚动、返回、启动应用、操作后回读 | 模型规划、会话存储、电脑命令执行 | 待建；现有 Kotlin 文件只提供生成/分享/上传等基础能力 |
| `remote_link` 设备连接 | 设备配对、身份与能力协商、连接状态、任务提交与事件续传 | 判断任务是否成功、直接操作目标主机内部数据库 | 待建；既有 SSH/MCP 连接仅提供部分参考 |
| `desktop_runtime` 电脑 Agent | Rust 服务独立持有任务、模型上下文、终端进程、文件变更、日志和产物 | 依赖手机在线才能进行每一个工具轮次 | 待建 |
| `desktop_cli` 电脑命令行入口 | 提交、查看、跟随、停止任务，展示文件差异与结果 | 自建第二套任务引擎或第二份任务状态 | 待建；调用电脑运行时公开接口 |

科研终端保留“交互会话”的模块身份。电脑 Agent 是“任务执行服务”。同一台电脑可同时提供这两种能力，但二者使用不同生命周期；关闭终端不能自动取消另一项 Agent 任务。

## 三、可复用能力

| ID / 模块 | 边界 | 当前定位 / 状态 |
| --- | --- | --- |
| `model_access` 模型访问 | 四协议、自动尝试、流式解析、用量、连接测试和模型能力；不读取产品数据库 | `domain/llm/`，旧长任务网关客户端另归兼容层；现有 |
| `content_capabilities` 内容能力组 | 下设搜索、文档、媒体、语音；每项有独立输入/结果与配置 | `domain/tools/`、`document/`、`media/`、`speech/`；现有但目录归属混合 |
| `mcp_connector` MCP 连接器 | HTTP/stdio 传输、初始化、发现、调用、资源读取与连接生命周期 | `domain/mcp/`；现有 |
| `document_service` 文档服务 | Python 文档 MCP、上传状态、文档 worker、文档文件 | `server/mcp_server/`、`server/document_core/`；现有 |

内容能力组内的职责必须保留：

- **搜索**：查询、抓取、来源与引用结果。现有 `ToolEngine` 主要是搜索编排，不能因为名字通用就把它直接认定为通用 Agent 引擎。
- **文档**：本地资料解析、文档修改/转换请求与产物。文档 MCP 有自己的文件标识和生命周期，不等于设备配对协议。
- **媒体**：视觉、生图、参考图准备；生成结果由工作资料模块登记为资产。
- **语音**：ASR、TTS、音频流与设备音频适配。对话页面拥有用户交互，语音服务不拥有整个聊天任务。

## 四、基础设施与兼容范围

| ID / 模块 | 边界 | 现状 |
| --- | --- | --- |
| `contracts` 公共契约 | 仅收纳跨模块/跨设备必需的任务、事件、目标、工具和产物语义；不收纳全部业务实体 | 当前散落在 `models`、LLM/MCP 类型与状态对象中；待形成独立边界 |
| `storage` 存储与恢复 | SQLite 连接、文件与安全存储机制、迁移设施、备份协调；业务实体由所属模块解释 | `data/db/`、文件 Store、备份服务；部分 |
| `platform_services` 平台与维护 | 通知、前后台生命周期、分享、剪贴板、更新、缓存、诊断、预览宿主；按子能力分区 | 当前分布在 `domain` 与各平台宿主；现有 |
| `legacy_gateway` 旧服务兼容 | 旧 Gateway/OIDC/REST/长任务适配；新任务服务通过明确适配接入，不隐式复用旧语义 | 旧客户端与 `server/gateway`、`doc_edit`、`authservice`；兼容保留 |
| `web_experiment` Web 原型 | 独立 React/Vinext 参考界面 | `remote_lab_ui/`；实验 |

## 五、已有结构的六项优化

| 当前结构问题 | 模块层面的优化 | 达成标志 |
| --- | --- | --- |
| 一个功能分布在 features/state/domain/data 四处 | 产品工作区按模块归口，状态与仓库成为模块内部实现 | 新开发者可从一个模块入口找到职责、数据、公开接口和测试 |
| 聊天入口同时承担多类任务编排 | 会话负责内容与呈现，运行模块负责执行 | 独立任务入口可运行同一任务；页面退出不改变任务的业务状态 |
| 全局 models/settings 成为业务交叉点 | 领域实体归业务模块；公共契约只保留最小交互语义；设置按模块配置片段聚合 | 模型访问无需导入故事/学习实体；新增工具不要求扩大所有工作区状态 |
| tools 目录同时放搜索、文件、媒体等 | 工具注册与具体能力实现分离，按能力组归口 | 注册新的执行器不修改会话、学习、创作的内部实现 |
| SSH、MCP、远程任务容易被统称为“连接” | 交互终端、工具协议、设备任务连接分别建模 | 断连、取消、授权与恢复含义各自明确 |
| 文档、旧 Gateway、Web 原型混合出现于总体架构 | 登记主产品、当前服务、兼容部署、实验工程四类状态 | 新开发不会误把旧 REST 或实验 UI 当成必须经过的生产主链路 |

## 六、当前跨模块实体的迁移原则

`data/models.dart` 和 `settings_state.dart` 暂作为兼容聚合点。迁移时先确定每类数据的唯一所属模块，再以公开接口替换跨模块访问；不为拆目录而复制同一个实体到 Dart、Rust、Kotlin 三处。

任务执行记录未来拥有独立身份，聊天消息只保存关联和展示快照。课程生成、图片生成、手机操作和电脑编码任务可以拥有不同输入与结果，但共同遵循任务状态和事件语义。
