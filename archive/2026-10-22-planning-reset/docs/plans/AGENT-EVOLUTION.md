# Android 手机 Agent 与电脑执行端：模块演进计划

> 状态调整：此文为增量演进备选。整体重构采用 [V2 实施计划](AGENT-V2-REBUILD.md) 的 V0–V5 顺序；下面的 P0–P6 不再作为主执行顺序。

日期：2026-10-22。当前授权范围为模块划分、依赖边界、目录方案和迁移计划。**只有 P0 的规划交付在本轮完成；P1–P6 为后续实施工作。**

产品前提：现有 Flutter 项目继续作为主要产品；Android 优先，手机 Agent 包括跨 App 观察、点击和输入；电脑需要独立命令执行、文件操作、Agent 任务与 CLI；手机可以远程提交和查看电脑任务。

## 1. 成功标准

最终交付应能演示三条完整链路：

1. 手机内正常聊天、学习、创作与资料使用继续工作，原有配置与备份可迁移。
2. 手机接收用户目标，在授权的测试 App 中完成多步操作，每步能说明依据、结果与停止原因。
3. 手机向已配对电脑提交编码/文件任务，电脑独立执行与验证；手机断连重连后仍能找到同一任务、查看过程、结果和文件差异。电脑 CLI 可操作这些任务。

验收以行为和证据为准。新增页面、目录、接口或编译通过均不能单独证明这些目标已完成。

## 4. P1：独立任务与能力接口

**要解决的问题**：新任务中心、手机执行器和远程电脑不能各自复制聊天控制器的执行逻辑。

涉及模块：conversation、agent_runtime、tool_registry、model_access、contracts、storage、task_workspace。

工作包：

1. 确定本机任务的输入、执行句柄、事件和取消语义，复用现有消息与工具结果类型。跨设备幂等与传输 Schema 留到 P3/P4。
2. 将已有预算、流生命周期、工具轮次、取消及核验收敛到运行模块；会话持有消息树并消费事件。
3. 让普通聊天先通过新任务接口执行，保持目前模型、搜索、文档、生图、MCP 的行为。
4. 增加最小任务查看入口，与聊天页订阅同一任务；先复用现有执行记录与保存机制，仅在独立任务身份确实无法表达时增加存储，不提前重写历史消息。
5. 验证运行模块能脱离 Widget 使用，代码审查公开依赖；跨语言样例随 P3/P4 的真实接口建立。

完成标志：

- 同一合成任务从聊天入口和任务入口启动，产生等价结果；改变页面可见性或关闭任务详情不隐式取消它。
- 任务执行期间切换会话/模型配置，目标与本轮快照不改变；迟到事件不写入另一会话。
- 停止、预算耗尽、工具失败、模型断流分别有明确结果；取消后不再接受新工具动作。
- 重启可读取旧任务记录；未完成有副作用步骤显示中断/待核验，不自动重复执行。
- 四协议、现有文档/生图/上下文、备份和现有全量客户端检查通过。

回退：采用小批次、可回退的变更并保留数据兼容。过渡适配在切换验收后删除，不长期维护两套聊天执行路径；若增加任务数据，回退不得删除记录或把新格式按旧长任务解释。

## 5. P2：Android 跨 App 操作原型

涉及模块：android_executor、agent_runtime、tool_registry、platform_services、task_workspace。

工作包：

1. 用 Kotlin 提供独立的观察与动作执行模块，经 Dart 适配器注册到能力目录。
2. 观察包含 App/窗口身份、可用控件、必要截图及观察版本；动作包含点击、输入、滚动、返回和启动应用。
3. 将动作结果和后续观察回送任务；明确权限撤销、目标改变、控件失效、取消与结果不确定。
4. 完成 Android 权限、服务生命周期、前台提示与用户停止入口；把发行渠道/使用目的记入产品决策。

完成标志（原型与发布验证分别推进）：

- 原型先用两个自有演示 App 和 3 条端到端任务，覆盖跳转、点击、文本输入、滚动和返回，每条重复 3 次；发布验证再扩展到至少 10 条任务。
- 覆盖权限未开/撤销、目标 App 切换、观察过期、屏幕不可读取、模型取消及执行服务被重建；失败原因可见，无法确定动作结果时不自动重发。
- 用户停止后 2 秒内不再派发新动作；已经提交给系统的动作不承诺撤销。
- 原型先在一台真实 Android 设备验收；发布前补齐至少两种 Android 系统版本，并记录设备型号、版本、用例和结果。
- 原有语音、分享接收、普通聊天和后台生成回归通过。

这些阈值是未来验收目标，当前没有测得的真机结果。涉及真实第三方 App 时，另行验证其控件可访问性和行为边界。

回退：手机操作能力可单独禁用；禁用后任务进入明确的不可用/待用户处理状态，聊天和内容工具仍可使用。

## 6. P3：Rust 电脑执行服务与 CLI 基础

涉及模块：desktop_runtime、desktop_cli、contracts、storage。首个验收平台为 Windows。

工作包：

1. 建立一个 Rust crate，提供服务和 CLI 两个入口；实现持久任务身份、状态、事件序号与产物清单。任务状态与普通有序日志足以支撑首版，不另建通用事件溯源平台。
2. 实现受限工作目录下的文件读取、列举、补丁修改、差异查看，以及命令执行、输出收集、超时与进程树终止。
3. CLI 使用同一服务接口提交、查看、跟随和取消任务。长任务由服务持有，不依附 CLI 窗口生命周期。
4. 明确 PowerShell、普通进程与交互式终端的能力差别，逐项验收；MCP 为可插拔能力来源。

完成标志：

- 在临时工作区执行读取、修改、运行测试和产物生成；边界外路径、错误工作目录、乱码/大输出均有确定处理。
- 使用父/子/孙进程测试取消与超时；明确确认整个本任务进程树的终止，不能只结束启动 shell。
- 重复提交相同幂等标识只返回一个任务；服务重启后已有记录与产物可查询。
- CLI 退出后，按任务的脱离终端策略继续执行或取消；策略在提交时可见。
- 该阶段可以先提供明确命令/工具任务，**不能因此宣称已完成电脑自主编码 Agent**。

回退：电脑执行能力可单独关闭或降级为只读工具；保留原科研 SSH 工作区和现有文档 MCP。

## 7. P4：电脑自主 Agent 与远程任务闭环

涉及模块：desktop_runtime、remote_link、desktop_cli、task_workspace、workspace。

工作包：

1. 电脑侧接入模型访问、上下文预算、工具循环和核验。原型先支持实际选用的一种模型协议，并迁入该协议已验证的测试样例；按接入需求补齐其余协议，不能假定 Dart 与 Rust 自动等价。
2. 支持电脑模型配置与秘密存储引用，让电脑能够独立执行；设备配对不自动复制手机全部密钥。
3. 实现配对、身份校验、能力协商、任务提交、事件订阅/续传、产物下载和取消确认。
4. 手机任务中心区分本机/电脑，展示连接状态、任务真实状态、待确认动作和产物。
5. 用“手机发起 → 电脑读取工程 → 修改 → 执行测试 → 回传差异与结果”建立端到端验收。

完成标志：

- 已声明支持的模型协议通过正常/失败/取消/工具往返一致性用例；原型只展示实际可用能力。四协议完整覆盖在 P5 兼容验收时补齐，自动尝试不重发已开始输出或执行中的动作。
- 至少 5 个合成工程任务，覆盖读取、补丁、命令失败后的修正、测试验证和产物；模型声称完成必须有执行证据。
- 手机离线 5 分钟后重连，仍能查询同一个任务和全部已提交事件，不产生重复任务。
- 事件重复、乱序和缺口通过投影去重与补齐处理；结果未知的写操作进入待核验，不能承诺任意命令恰好执行一次。
- 配对撤销后旧凭据不能继续提交/读取任务；切换选中电脑不改变运行任务的目标。
- 手机取消只有收到执行端确认后显示已停止；产物校验失败不会保存成成功文件。

回退：关闭远程 Agent 入口并保留任务只读记录；旧文档 Gateway 任务由兼容层继续识别，不混用新任务身份。

## 8. P5：模块目录归口与产品整合

按 [目标目录](../architecture/TARGET-STRUCTURE.md) 逐批归口，先模型与独立工作区，后工作资料/设置，最后会话与运行模块交界。每批包含所有者、公开入口、依赖检查、测试归属、文档路径与回退说明。

产品入口安排：

- 会话：表达目标和讨论结果。
- 任务中心：查看所有执行过程、待确认动作与结果。
- 设备与连接：管理手机能力、电脑配对及在线状态。
- 学习/创作/资料/科研：继续作为有明确业务数据的工作区，按需调用任务能力。
- 设置：管理模型、能力和偏好，不兼任任务操作页。

完成标志：没有新增跨模块内部访问和依赖环；契约不依赖 UI/具体存储；新旧用户数据和 v15/v16/v17 备份按实际支持范围恢复；同一产物在任务、会话和资料库中拥有一致引用；电脑端四协议兼容验收补齐后再声明与手机端一致；当前产品检查与对应 Android/电脑实机验收完成。

## 9. P6：共享 Rust 核心的决策门槛

在 Dart 手机运行时和 Rust 电脑运行时都稳定后，测量重复维护成本与调用边界。若模型适配、上下文、事件和任务规则长期出现重复修复，且 Rust 库能在目标 Android ABI 上稳定打包、取消、回调与诊断，再迁移共享核心。

迁移时 Kotlin 仍拥有 Android 系统 API 和服务生命周期，Flutter 仍拥有产品界面；Rust 共享库只负责已经验证可以共享的领域能力。iOS、Linux/macOS、独立 Web 客户端、账号同步分别建后续计划，不作为当前 Android + Windows 闭环的隐含交付。
