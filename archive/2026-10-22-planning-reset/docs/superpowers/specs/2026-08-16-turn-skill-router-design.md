# 会话内本轮 Skill 路由设计规格

**日期**：2026-08-16  
**状态**：已与用户对齐（普通对话内、仅本轮、当前对话模型分类、JSON 路由、目录可改可增）  
**产品**：Expert Chat

---

## 1. 背景与目标

设置里的「预设提示词」现在是一条全局系统提示：只要非空，普通对话和学习都会整段注入。用户希望在**同一个普通对话**里，按本轮任务选用不同提示词，并且自己改提示词、自己加任务种类。

这不是新的会话模式，也不替代故事 / 学习 / 乱斗已有的契约。

### 1.1 成功标准

- 普通对话每一轮独立选一个 skill，注入该类提示词后再生成。
- 分类器用当前对话模型，只输出 JSON；候选种类来自用户当前的 skill 目录。
- 用户能改每条提示词，也能新增种类；新增后下一轮分类即可选中。
- 分类失败不阻断发送，回退到兜底 skill。

### 1.2 非目标

- 不按会话模式路由（故事 / 学习 / 乱斗不走这层）。
- 不把 skill 粘在会话上；下一轮重新分类。
- 不为分类单独配置第二个模型。
- 不做开放标签或自由文本 skill id。
- 不把所有 skill 提示词一次性塞进主生成的系统提示里让模型“自己挑”。

---

## 2. 数据：一份 JSON 目录

Skill 目录是设置里的一份 JSON 数组，和现有 `systemPrompt` 一样持久化。分类器和注入都只读这份目录。

```json
[
  {
    "id": "general",
    "name": "通用",
    "when": "闲聊、问答、无法归入其它种类时",
    "prompt": "用简洁中文直接回答；先给结论；不确定就说明不确定。",
    "prefix": "/通用",
    "enabled": true,
    "fallback": true
  },
  {
    "id": "writing",
    "name": "写作",
    "when": "润色、续写、改文体、写正文",
    "prompt": "……",
    "prefix": "/写作",
    "enabled": true
  }
]
```

| 字段 | 用途 |
|------|------|
| `id` | 稳定键；分类器 JSON 只能返回目录里已有的 id |
| `name` | 界面标签 |
| `when` | 只给分类器看的选用说明 |
| `prompt` | 本轮注入的系统提示正文 |
| `prefix` | 可选；本轮以该前缀开头则跳过分类 |
| `enabled` | 关闭后不参与分类、不能被注入 |
| `fallback` | 恰好一条为 true；失败时走它 |

添加 skill = 往数组里追加一个对象。下一轮分类请求会带上新的 `id/name/when`，不必改分类器代码。

现有 `systemPrompt` 一次性迁进 `id=general` 的 `prompt`；空则用出厂通用文案。之后设置页编辑这份目录，不再只显示一个大文本框。

内置出厂条：通用、写作、代码、翻译、总结。均可改 `name/when/prompt/prefix`。自定义可删。必须始终存在恰好一条启用的 `fallback`。

---

## 3. 分类器契约

只在 `ConversationMode.chat` 调用。使用当前会话的对话模型（同一 Provider / Key / Base URL，取非深度思考的 chat 模型），`thinking: false`，短输出。即使本轮正文开了深度思考，分类也不走 reasoner。

输入：本轮用户正文（去掉已识别前缀）+ 最近至多 2 轮对话，以及当前启用 skill 的 `id/name/when`（不含各 skill 的长 `prompt`）。

只允许输出一个 JSON 对象，不要 Markdown 围栏：

```json
{"skill":"writing","confidence":0.82}
```

`skill` 必须是本轮启用目录中的某个 `id`。

### 3.1 选用顺序

1. 本轮文本以某条启用 skill 的 `prefix` 开头 → 用该 id，标记为指定。
2. 否则跑分类器。
3. `skill` 不在启用目录、缺字段、JSON 解析失败、超时、或 `confidence < 0.6` → fallback id，标记为回退。
4. 分类异常不抛给用户，不取消正文生成。

分类系统提示写死：列出候选种类，要求只输出上述 JSON。种类列表每次从目录生成。

---

## 4. 发送链路

发生在 `_generate` 里、组装普通对话系统消息之前：

1. 非 chat 模式：跳过整层。
2. 解析前缀或调用分类器，得到 `skillId`。
3. 用 `id` 查目录，取 `prompt`；空则视为该 skill 不注入额外系统消息。
4. 用该 `prompt` 替换今天无条件注入的 `settings.systemPrompt`。
5. 记忆、工具提示、联网、生图逻辑不变，仍按原顺序追加。
6. 把 `{skillId, source: prefix|model|fallback}` 记在本轮助手消息元数据上，供气泡显示「本轮：写作」。只表示这一轮。

分类请求与正文串行：先分类再生成。分类超时 10s，超时走 fallback。

---

## 5. 界面

- **设置 → 预设提示词**：目录列表。可改每条字段、停用、新增、删除自定义。新增时至少要有名称和 `when`，否则分类器难以选中。
- **对话**：输入栏不强制先选 skill。生成开始后，该助手消息显示本轮种类；前缀指定与自动判断用不同副文案。
- 输入 `/` 可提示已启用 prefix，作为覆盖，不是必选。

---

## 6. 错误处理

| 情况 | 行为 |
|------|------|
| 分类超时 / 网络失败 / 非 JSON | fallback，正文继续 |
| 未知 skill id | fallback |
| 目录损坏或为空 | 运行时回落到出厂目录 |
| fallback 被删光 | 保存时拒绝；读盘时自动恢复出厂通用条 |
| 两条 fallback | 保存时只保留一条（优先 `general`） |

---

## 7. 测试

- 前缀覆盖：`/代码 …` 不调用分类器，注入代码 prompt。
- 分类器返回合法 id：注入对应 prompt，不注入其它 skill prompt。
- 返回未知 id / 坏 JSON / 超时：注入 fallback。
- 新增一条自定义 skill 后，分类提示词的候选列表包含它。
- 停用的 skill 不出现在候选里，前缀也不再生效。
- 故事 / 学习会话不调用分类器，也不注入该目录。
- `systemPrompt` 旧值迁入 `general.prompt`。

## 8. 实现落点（实现时再拆计划）

- 新模型：`ChatSkill` + 目录编解码（settings 一串 JSON）。
- `SettingsController`：读写目录、迁移旧 `systemPrompt`、校验 fallback。
- 新服务：`ChatSkillRouter`（前缀解析 + 分类调用 + JSON 解析）。
- `ChatController._generate`：chat 模式插入路由，替换全局 preset 注入。
- 设置页列表编辑；消息气泡展示本轮 skill。
