# Expert 终端界面（TUI）设计规格 v2

本文件最初替代 `expert-terminal.html` 的网页式设计，`tui-redesign.html` 只是视觉参考。

> 2026-10-26 修订：选择器使用居中弹窗；新增共享 Host、计划审核、任务总览、检查点与阅读定位。本文描述目标行为，当前新增代码仍待统一验收，进度见 [主规划第 23 节](../../docs/PROJECT-PLAN.md#23-gui--tui-共享执行与交互改造计划2026-10-26)。

## 0. 原则

1. **字符网格优先**。所有尺寸以「列 / 行」为单位，只有一种字号；层级只靠颜色、亮度（dim）、粗体和缩进表达。不存在 px、行高、圆角、阴影。
2. **对话是主角，外框最少**。没有顶部标题栏和导航栏。固定界面元素在 80×24 下最多占 6 行：状态行 1 + 输入框 3 + 底栏 2。
3. **尊重终端主题**。不设置背景色（只有差异行和选中项例外），默认只用 ANSI 16 色，真彩色是增强。
4. **键位可靠**。不使用 F 键，不占用 readline 编辑键和终端流控键。
5. **危险状态一直可见**。完全访问、计划模式、待批准必须在固定区域显示，不能藏在浮层里。

## 1. 屏幕结构

```
┌ 记录区 ────────────── 可滚动，占满剩余高度
│
├ 状态行 ────────────── 1 行，仅在运行 / 待批准 / 重试 / 待验收时出现
├ 输入框 ────────────── 3 行起（边框 2 + 内容 1），随内容增长，最多 8 行
└ 底栏 ──────────────── 2 行：工作区/模型/权限，以及上下文/用量；打开命令补全时被补全列表替换
```

- 浮层（模型、权限、会话、帮助、设置、计划与检查点）使用**居中弹窗**，有边框与关闭按钮，弱化后方内容。布局保留底部错误/旧快照提示；缩小窗口时当前选项和操作仍可达。批准与提问卡继续放在记录区下方，不改变其等待语义。
- 全屏视图（改动、任务树）使用备用屏幕，`q` / `esc` 返回。
- 窗口标题（OSC 0/2）设为 `expert · <会话名>`，代替原来的顶部栏。

### 启动页（80×24）

启动页不是单独的页面，而是记录区的第一块内容，所以叫「欢迎块」。用户发出第一条消息后，它随记录区一起往上滚走，留在回滚记录里。欢迎块不重复底栏已经显示的信息（位置、模型、权限），只显示底栏没有的内容。

```
                                                          ░░░░░░░░░░░░░░░░░░░░
  最近会话                                                         /resume
    ● 自适应图片预览                                    运行中 · 2 分钟前
    ○ 接口回归检查                                        待验收 · 昨天
    ○ 实验结果汇总                                        已结束 · 3 天前

  / 命令   @ 文件   ? 快捷键   shift+tab 计划模式







╭──────────────────────────────────────────────────────────────────────────────╮
│ › 描述任务，/ 命令，@ 文件                                                   │
╰──────────────────────────────────────────────────────────────────────────────╯
  ⌂ image-lab › main   GPT-6 Sol · 高   ◇ 请求批准
```

- 第一行：`◈` 用 accent，`expert` 粗体（品牌行是粗体规则的唯一例外），版本号 muted。
- 项目块：项目名用 fg，路径用 muted。第二行是 git 分支和未提交改动数，不是 git 仓库时省略。第三行列出已加载的上下文，项为 0 时省略该项。
- 最近会话：只列当前工作区的会话，最多 3 条，状态字形规则同 §7.3。运行中的会话（可能正在 GUI 里跑）用 accent 的 `●`。会话在这里只展示，不可选中；用 `/resume` 打开选择浮层，`/resume` 后直接回车则继续最近的一条。没有历史会话时整块省略。
- 提示行：键名用 accent，说明用 muted。用户发出第一条消息后，这一行不再出现。
- 输入框获得焦点，空闲时不显示状态行。

**变体：**

| 情况 | 欢迎块的变化 |
|---|---|
| 首次运行，没有可用模型 | 用一个 warn 色的块替换「最近会话」，内容为 `还没有可用的模型` / `/login 登录官方订阅   /model 添加 API 来源`。输入框占位文字改为 `先登录或添加模型来源`，发送时直接打开 `/login`。 |
| 当前目录不是项目（如 `~`） | 项目块显示 `默认工作区  ~/Documents/Expert`（muted）和一行提示 `用 expert <目录> 在项目中启动` |
| 启动时出错（MCP 服务失败、配置损坏） | 在项目块下方加一行 warn：`! playwright 启动失败 · /mcp 查看`；多个错误时合并为 `! 2 个问题 · /doctor 查看` |
| 用 `expert resume <id>` 或 `expert "任务"` 启动 | 不显示欢迎块，直接进入会话或开始执行 |
| 宽度 < 60 | 最近会话只保留会话名和状态字形，去掉时间 |
| 高度 < 16 | 只保留第一行和提示行 |

### 启动页宠物：惠惠

欢迎块右上角有一个像素小人，点击会切换动作。

**素材**
- `pet/megumin.json`：调色板和 9 帧像素图，每帧 20×12 像素。`.` 表示透明，其他字符是调色板里的键。
- `pet/megumin-sheet.png`：这 9 帧的总览图，只用于查看。
- 实现时直接读取 JSON，不要把像素图手写进代码。

**位置与绘制**
- 占用 20 列 × 6 行：第 0–5 行，第 `宽度−22` 到 `宽度−3` 列，右侧留 2 列边距。宠物只和品牌行、项目块并排，底部停在「最近会话」上面的空行，不碰会话列表。
- 每个字符格画上下两个像素：
  - 上下都有颜色：用 `▀`，前景色取上像素，背景色取下像素。
  - 只有上像素：用 `▀`，只设前景色。
  - 只有下像素：用 `▄`，只设前景色。
  - 都透明：空格，不设背景。
  - 透明像素一律露出终端自己的背景，不能填色。
- 「最近会话」的 `/resume` 提示保持在行尾。
- 台词显示在第 1 行（这一行左侧本来是空的），右对齐到宠物左边 2 列处，用 accent 色和「」括起来。显示 2.5 秒后消失。

**动作**

一共 4 个状态，点击按下面的顺序循环推进：

| 状态 | 帧序列 | 台词 | 点击后 |
|---|---|---|---|
| 待机 | `idle`；每 3–6 秒随机眨一次眼（`blink` 停 150ms） | 无 | 第 1、3、5…次点击进入「自我介绍」，第 2、4、6…次进入「爆裂魔法」 |
| 自我介绍 | `pose` 停 1.6 秒，然后回到 `idle` | 「吾名惠惠！」 | 动画播放中点击无效 |
| 爆裂魔法 | `chant1` / `chant2` 交替，每帧 200ms，共 4 次 → `boom1` 120ms → `boom2` 450ms → `boom3` 600ms → `down` | 依次显示「比黑更黑……」「Explosion！」 | 动画播放中点击无效；结束后停在 `down` |
| 倒地 | `down`，一直保持 | 「……动不了了。」 | 点击回到 `idle`，台词「明天还要再放一发。」 |

- 鼠标点击需要开启鼠标捕获（底栏的点击功能本来就需要）。在帮助（`?`）里写明：按住 `shift` 拖动可以选中文字，多数终端都支持。
- 键盘触发：`/pet` 的效果等同于点击一次；`/pet off` 关闭宠物，并写入配置 `pet = "none"`。

**何时显示**
- 同时满足以下条件才绘制宠物：
  - 宽度 ≥ 80，高度 ≥ 20
  - 支持真彩色或 256 色（256 色时取 xterm 调色板中最接近的颜色）
  - UTF-8 环境，`ambiguous_width = 1`
  - 未设置 `NO_COLOR`
  - 配置 `pet` 不为 `none`
- 不满足时不显示宠物，也不留空位，欢迎块恢复成没有宠物的布局。
- 宠物随欢迎块一起滚出视野后，停止所有计时器，不再占用 CPU。
- 减少动画模式（见 §13）下不眨眼。点击后直接显示每段动作的最后一帧：自我介绍显示 `pose` 1.6 秒后回到 `idle`，爆裂魔法直接跳到 `down`。台词照常显示。
- 深色终端上，帽子主色 `K` 改用 `#3d3448`，否则帽子会和背景混在一起；浅色终端使用 JSON 中的原值。

## 2. 视觉系统

### 2.1 颜色令牌

| 令牌 | ANSI 16 | 真彩 · 深色背景 | 真彩 · 浅色背景 | 用途 |
|---|---|---|---|---|
| `fg` | 默认前景 | 默认 | 默认 | 正文 |
| `muted` | 默认前景 + DIM | `#8a9aa3` | `#66767e` | 元信息、路径、提示、占位文字 |
| `accent` | cyan (6) | `#7cc0de` | `#1f6283` | `›` `◈`、输入框边框、选中项、链接 |
| `good` | green (2) | `#8fcca8` | `#2a7350` | ✓、新增行数 |
| `warn` | yellow (3) | `#e3bc72` | `#87591a` | 待批准、重试、运行中的数字 |
| `bad` | red (1) | `#eaa1a8` | `#a83e48` | ✗、删除行数、完全访问 |
| `add-bg` | 无（只用前景色） | `#1c3326` | `#e6f3ea` | 差异视图新增行背景 |
| `del-bg` | 无 | `#3a2226` | `#f8e6e8` | 差异视图删除行背景 |
| `sel` | REVERSED | REVERSED | REVERSED | 列表当前项 |

- 真彩色：仅在 `COLORTERM` 为 `truecolor` / `24bit` 时启用。明暗通过 OSC 11 查询背景色，超时 100ms；失败时读 `COLORFGBG`；再失败按深色处理。
- `NO_COLOR` 已设置时去掉所有颜色，只保留粗体、DIM 和反显。
- muted **不要用** ANSI 8（bright black）：在 Solarized 等主题下几乎看不见。

### 2.2 文字样式

- **粗体**只用于：启动页品牌行、浮层标题、`▲ 完全访问`、Markdown 标题。
- 不使用斜体（中文斜体很难看）。
- 下划线只用于 OSC 8 超链接（文件路径可点击，在编辑器或 GUI 中打开）。

### 2.3 字形

| 含义 | 字形 | ASCII 回退（`--ascii` 或非 UTF-8 环境） |
|---|---|---|
| 用户消息 | `›` accent | `>` |
| 助手消息 | `◈` accent | `*` |
| 完成 / 失败 | `✓` good / `✗` bad | `v` / `x` |
| 运行中 | 盲文转圈 `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`，80ms 一帧 | `-\|/` |
| 等待中 | `◌` muted | `.` |
| 输出尾部 | `│` muted | `\|` |
| 思考 | `∴` muted | `~` |
| 请求批准 / 自动审查 / 完全访问 | `◇` muted / `◆` accent / `▲` bad 粗体 | `?` / `+` / `!` |
| 计划模式 | `▣ 计划` warn | `[plan]` |

不使用 emoji。

### 2.4 间距

- 消息之间空 1 行；一组步骤行之间不空行。
- 缩进：消息 0 列，步骤 2 列，输出尾部 4 列。
- 助手正文换行宽度 = `min(终端宽 − 4, 100)`，保证宽屏下仍然好读。

## 3. 记录区组件

### 3.1 用户消息
`› ` 用 accent，正文用 fg，续行缩进 2 列。附件另起一行显示：`  ⎘ screenshot.png · 1.2 MB`（muted）。

### 3.2 助手消息
`◈ ` 后接 Markdown 渲染，规则如下：
- 标题：粗体 + accent
- 列表：`•`
- 行内代码：accent
- 代码块：左侧加 `│` muted 竖线，语法高亮，不加背景
- 表格：使用框线字符

### 3.3 步骤行（工具调用）
```
  <状态> <动词>  <对象>                                  <右侧元信息>
```
- 动词固定 2 个汉字（4 列宽），保证对象列对齐：`读取 编辑 新建 删除 运行 搜索 浏览 助手 思考 联网`。
- 对象（路径、命令、查询）用 fg；对象过长时**截断中间**：`lib/…/preview.dart`。
- 右侧元信息（muted）：编辑类显示 `+18 −6`，其中加号部分 good、减号部分 bad；运行类显示耗时，失败时显示 `退出码 1`（bad）；助手类显示 `ctrl+t`。
- 运行中的命令在下面显示最近 2 行输出，前缀 `    │ `（muted），结束后去掉。失败时保留最后 3 行，便于直接看出原因。

### 3.4 折叠规则
- 每组步骤先显示摘要：`工具进展 · 4/5 步完成 · 1 进行中`，有失败或跳过时在末尾追加数量，右侧提供 `[查看记录]`。
- 成功轮次结束后只保留摘要；运行中或展开时最多显示 3 个步骤，优先保留失败、运行中和待批准步骤，再补最近步骤，并按原顺序排列。
- 即使轮次已经结束，失败步骤也不折叠隐藏：保留失败状态、退出码和最后 3 行输出，后续成功步骤不能把失败证据挤掉。
- `ctrl+o` 切换「全部展开 / 全部折叠」，作用于整个记录区。

### 3.5 思考
折叠为一行：`  ∴ 思考  12s`。展开后以 muted 显示全文，左侧加 `│` 竖线。

### 3.6 交付摘要（一轮结束且有文件改动时）
```
◈ 已完成。预览改为按容器宽高的较小比例缩放；手动缩放仍然优先。

  ✓ 5 个步骤 · 1m58s                                           ctrl+o 展开

  改动  2 个文件  +42 −6                                   ctrl+g 查看差异
    M lib/preview.dart                    +18 −6   自适应比例与手动缩放
    A test/preview_test.dart                 +24   窗口尺寸和比例回归
  检查  ✓ flutter test · 4 通过 · 退出码 0
```
- 改动类型 `M A D R`：M 用 warn，A 用 good，D 用 bad，R 用 accent。
- 交付摘要里只列出**本轮实际产生的**改动，必须和步骤行一致（旧设计中「交付文件 · 2」和步骤记录对不上）。

### 3.7 错误
- 工具失败：步骤行状态为 `✗`（bad），保留输出尾部 3 行，随后由助手接着说明原因。
- 请求失败、重试：只在状态行显示，不写进记录区。全部重试失败后，才在记录区写一行 `  ✗ 请求失败 · 401 密钥无效 · /model 切换来源`。

## 4. 状态行

状态行与输入框之间不留空行，右侧显示当前可用的操作提示。

| 任务状态 | 左侧 | 右侧 |
|---|---|---|
| 运行中 | `⠹ 运行检查 · 第 4/24 轮 · 1m42s`（转圈用 accent，其余 muted） | `esc 中断` |
| 第一次按了 esc | `再按一次 esc 中断任务`（warn） | |
| 待批准（批准卡已收起） | `◇ 1 个操作等待批准`（warn） | `ctrl+y 处理` |
| 重试 | `! 429 速率限制 · 8s 后重试（2/5）`（warn） | `esc 中断` |
| 待验收 | `✓ 检查完成 · 待验收`（good） | `/accept 验收 · 直接输入修改意见` |
| 已停止 | `■ 已停止 · 第 4/24 轮`（muted） | `enter 继续` |
| 空闲 | 不显示该行 | |

已排队的补充要求显示在状态行上方，muted：
`  ↳ 下一轮发送：也检查一下深色模式`，按 `↑` 可取回编辑。

## 5. 输入框

- 圆角框线 `╭╮╰╯`。获得焦点时边框用 accent，浮层打开时用 muted。
- 行首是 `› `（accent）。占位文字（muted）：空闲时为 `描述任务，/ 命令，@ 文件`，运行中为 `输入补充要求，下一轮发送`。
- 粘贴超过 5 行时折叠显示为 `[已粘贴 48 行]`，发送时展开为原文。
- 已附加的图片或文件显示为输入框上边框里的标签：`╭─ ⎘ 2 个附件 ───…`。

### 5.1 批准卡（替换输入框）
```
◇ 等待你批准 · 第 4/24 轮
╭─ 运行命令 ───────────────────────────────────────────────────────────────────╮
│ flutter test test/preview_test.dart                                          │
│ 目录 ~/image-lab · 原因 验证缩放回归                                         │
│                                                                              │
│ y 允许一次   a 本会话允许 flutter test   n 拒绝   e 拒绝并说明               │
╰──────────────────────────────────────────────────────────────────────────────╯
```
- 边框用 warn。批准卡显示期间，`y` `a` `n` `e` 是单键操作（此时没有文本输入，不会冲突）。
- 写文件类操作在卡内显示 diff 预览，最多 8 行，`ctrl+g` 查看完整差异。
- `esc`：收起批准卡，回到普通输入框，任务保持阻塞，状态行提示 `ctrl+y 处理`。**esc 永远不等于拒绝或批准。**
- `e`：卡片变成一行输入框，填写拒绝理由，`enter` 提交。

## 6. 底栏

```
  ⌂ image-lab › preview-fix   GPT-6 Sol · 高   ◇ 请求批准         上下文 38%
```
- 各段之间空 3 格，不使用 `·` 或 `|` 分隔。工作区用 fg，分支、思考强度、上下文百分比用 muted。
- 上下文用量 ≥ 80% 时改为 warn，≥ 95% 时改为 bad，并加提示 `/compact`。
- 计划模式时在最左侧加 `▣ 计划`（warn）。
- 完全访问时显示 `▲ 完全访问`（bad 粗体），任何宽度下都不省略。
- SSH 工作区用 `⌁ 主机名` 代替 `⌂`。
- 支持鼠标时，点击各段打开对应浮层。
- **宽度不够时的省略顺序**：上下文 → 分支名 → 思考强度 → 模型名缩写（`Sol`）→ 工作区只留图标。权限段始终保留。

## 7. 浮层与补全

### 7.1 命令补全（输入框开头输入 `/`）
补全列表出现在输入框**下方**，替换底栏，最多 8 行：
```
╭──────────────────────────────────────────────────────────────────────────────╮
│ › /mo                                                                        │
╰──────────────────────────────────────────────────────────────────────────────╯
  /model         切换模型与思考强度
  /mode          工作模式 / 计划模式
  /permissions   工具权限
```
- 当前项用 sel（反显），命令名用 accent，说明用 muted。
- `tab` 补全；`enter` 执行；`↑↓` 或 `ctrl+n` / `ctrl+p` 移动；`esc` 关闭。
- `@` 文件补全行为相同，列表内容为工作区文件，按模糊匹配排序，路径中匹配的字符用 accent 标出。

### 7.2 模型（`/model`，或点击底栏模型段）

## 8. 键位

输入框默认获得焦点。

| 键 | 作用 |
|---|---|
| `enter` | 发送；运行中则排队到下一轮 |
| `Alt+J`、`Ctrl+J` / `Shift+Enter`（终端可区分时） | 换行 |
| `Alt+E` | 外部编辑器编辑当前草稿，返回后不自动发送 |
| `↑` / `↓`（输入框为空时） | 历史记录；有排队内容时 `↑` 先取回排队内容 |
| `esc` | 有浮层或补全时关闭它；运行中第一次按下显示确认提示，1.5 秒内再按一次中断任务；其他情况无操作 |
| `ctrl+c` | 有选区时优先复制；无选区时清空输入 / 中断运行；空闲空输入时第二次确认退出 |
| `shift+tab` | 在工作模式和计划模式之间切换 |
| `ctrl+o` | 展开或折叠执行详情 |
| `ctrl+g` | 改动视图（全屏） |
| `ctrl+t` | 任务树（全屏） |
| `ctrl+y` | 处理待批准操作 |
| `ctrl+b` | 侧栏开关（终端宽度 ≥ 140 列时） |
| `ctrl+r` | 历史搜索 |
| `ctrl+l` | 重绘 |
| `ctrl+v` | 粘贴图片（剪贴板中有图片时） |
| `pgup` / `pgdn`、鼠标滚轮 | 滚动记录区 |
| `/` `@` `?`（输入框为空且在行首时） | 命令 / 文件 / 帮助 |

**刻意不使用的键**：
- F1–F12：macOS 需要按 fn，tmux 和 SSH 下不可靠，F1 常被终端占用。
- `ctrl+s` / `ctrl+q`：终端流控（XON/XOFF）。
- `ctrl+a e k u w b f h d`：readline 编辑键。
- `ctrl+z`：挂起进程。

全屏视图和浮层内部没有文本输入，可以使用单键操作（`j/k`、`q`、`space`）。

## 10. 宽度适配

| 宽度 | 行为 |
|---|---|
| < 60 | 步骤行不显示右侧元信息；底栏只保留权限段和模型名缩写；隐藏状态行右侧提示 |
| 60–99 | 默认布局，底栏按 §6 的顺序省略；改动视图上下排布 |
| 100–139 | 改动视图左右分栏 |
| ≥ 140 | 可打开侧栏；正文换行宽度仍不超过 100 列 |

高度 < 16 行时，输入框最多 3 行，浮层最多 6 行。

## 11. 状态一致性

所有界面元素从同一份任务状态派生，不允许分别手动设置文字：

| 任务状态 | 步骤字形 | 输出尾部 | 状态行 | 交付摘要 |
|---|---|---|---|---|
| 运行中 | ⠹ | 最近 2 行 | 运行… | 不显示 |
| 待批准 | ◌（被阻塞的那一步） | 无（尚未运行） | ◇ 等待批准 | 不显示 |
| 失败 | ✗ | 最后 3 行 | 显示助手接下来的动作 | 不显示 |
| 待验收 | ✓ | 收起 | ✓ 待验收 | 显示 |
| 已验收 | ✓ | 收起 | 不显示 | 显示，标题改为 `已验收` |
| 已停止 | ■（中断的那一步） | 保留 | ■ 已停止 | 有改动时显示，标为 `未完成` |

旧设计的问题：待批准时检查步骤仍显示「正在运行…」。

## 13. 实现建议（不限制技术栈）

- 如果使用 Rust：ratatui + crossterm，宽度计算用 `unicode-width`。
- 所有对齐都按显示宽度计算：中文 2 列。● ○ ◇ ◆ ▲ │ ─ 等属于 East Asian Ambiguous 宽度字符，默认按 1 列计算，并提供配置项 `ambiguous_width = 2`，供 CJK 语言环境下把它们显示成 2 列的终端使用。
- 截断都在显示宽度上进行，不能切断一个汉字。
- 动画只有转圈一处。当 `TERM=dumb`、输出不是 TTY 或设置了 `EXPERT_REDUCE_MOTION` 时，改为静态 `◌`。
- 退出时向普通屏幕打印一行摘要：`expert · 自适应图片预览 · 2 个文件 +42 −6 · expert resume <id>`。
