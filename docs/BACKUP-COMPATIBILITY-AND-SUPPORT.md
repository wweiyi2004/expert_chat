# 第三轮：备份兼容与问题反馈（2026-09-07）

2026-10-15 更新：当前应用结构为 v17，完整备份容器仍为 v1。已支持 v15/v16 → v17 转换，旧生图记录的 `api_format` 为 null，不猜测协议。下文的 v16 说明及验收数量保留为第三轮发布时记录；当前适配见 [Gemini](GEMINI.md)。

## 备份兼容

- 完整备份的容器格式仍为 `ECBACKUP` v1，当前应用数据结构仍为 v16。
- 增加显式的 v15 → v16 转换：为旧会话补充空项目关联，补充空的项目、项目资料关联和生图版本表，再执行当前版本的完整字段、类型、引用和 SHA-256 校验。
- 兼容的是符合已知结构的完整备份，不代表所有旧软件版本的导出文件都能导入。更早的 JSON/Markdown 等格式不能伪装为 `.ecbackup`；转换测试使用构造档案和实际 v15 SQLite 表快照，不声称验证了未提供的历史发布备份文件。
- 未知旧版本、更新的数据版本、未知表/字段及非法元数据在写入前被拒绝。不会通过丢弃未知字段来勉强导入。
- 预览显示源版本和目标版本；旧会话恢复为“未归类”的新副本，不补造原备份没有的项目或生图记录。现有 v16 备份直接使用。
- 原有的恢复日志、SQL 提交标记、素材校验及副本导入机制继续生效。备份上限仍为 128 MB，且不加密。

## 帮助与反馈

入口在设置 → 数据 → 关于与更新 → 帮助与反馈。应用启动失败时也可进入独立的诊断摘要页面，无需数据库或 ProviderScope 成功初始化。

- 摘要采用明确的字段白名单：应用版本、平台、数据/备份版本、错误类别。
- 数据数量默认不读取，用户勾选后才查询聚合数量；不读取会话正文、文件名、模型端点或安全存储密钥。
- 取消勾选后，迟到的统计结果不会重新进入摘要。
- 版本信息或统计读取有等待上限；统计读取失败仍可提供基础报告。
- 用户可先预览，再复制摘要。打开反馈页只打开 GitHub 页面，URL 不携带报告内容，不自动提交。
- 错误卡片的技术信息增加本地路径脱敏，覆盖常见 Windows、UNC 与移动存储路径。诊断摘要本身不包含错误原文。
