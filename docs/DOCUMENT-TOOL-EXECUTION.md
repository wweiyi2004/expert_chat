# 文档与 MCP 工具执行

文档检查、修改、格式转换和发现式 MCP 工具调用已从 `ChatTools` 抽入 `DocumentToolExecutor`。执行器不依赖 Riverpod、`SettingsState` 或当前会话；通过注入的客户端和回调处理请求与结果。

## 职责边界

- `DocumentEditTools` 继续提供工具描述、参数解析和检查文本；`DocumentPatch` 与 `DocumentConvert` 继续校验补丁和转换规则。
- `DocumentToolExecutor` 选择源附件，校验可用能力、原始字节和文件格式，执行一次请求，统一将文件结果转换为附件，并发布执行步骤和错误。
- `DocumentServiceClient` 保留鉴权、能力检查、上传、MCP 调用和资源下载协议。
- 控制器保留模型可见工具选择、预算、MCP 名称路由、会话状态、步骤结果记录和持久化。执行回调绑定发起时的会话与助手消息，切换到其他会话不会改变文件归属。

MCP 请求使用路由后的原始工具名和对应服务器连接；执行记录仍使用模型看到的工具名。空白参数按空对象处理，非对象或损坏 JSON 在调用客户端前返回错误。工具可返回文本、文件、两者或空结果。

## 附件与修改约束

源附件继续取自本轮用户消息。指定名称时支持忽略大小写匹配，未找到时返回错误；未指定名称时优先选择保留原始字节的文档。检查附件只读取已提取文本，不发起远端请求，也不要求保留原始字节。

编辑和转换继续检查服务能力、原始文件字节、补丁格式和转换矩阵。提取文本被截断的文件禁止使用 `set_text` 整篇覆写，允许针对性 `replace_text`。无效参数、格式冲突和损坏 Base64 不会触发上传。

成功后先将输出文件附到原助手消息，再将步骤标记为完成。文件名、MIME、大小和下载字节来自客户端返回结果，不覆盖用户源附件。

## 取消与恢复

请求前和返回后均检查任务是否仍活跃及取消令牌。已经取消的调用不发送请求；取消后的迟到结果不会创建附件或标记成功。客户端包装后的异常若伴随已取消令牌，按取消处理，不作为服务故障展示。

保留既有恢复规则：文档与任意 MCP 步骤不开放 `retryTaskStep` 重放；失败时保留参数和结果以供查看。执行器自身也不自动重试。客户端取消不能证明服务器撤销了已收到的修改，后续由模型或用户重新发起的独立调用也不在本次去重范围内。

## 验证

`test/document_tool_executor_test.dart` 新增 27 项测试，覆盖附件选择、能力与补丁校验、截断保护、转换参数、文件发布顺序、MCP 返回形式、三类远端调用的请求前取消与迟到结果、错误分类。

控制器集成测试覆盖检查后转换的工具回复与步骤记录、失败文档/MCP 不可重放、切换会话后的文件归属、停止后不落文件，以及同名 MCP 工具的服务器路由。原有 MCP 客户端协议测试继续验证上传、调用和下载。所有服务均使用本地替代实现，未调用真实文档服务器。
