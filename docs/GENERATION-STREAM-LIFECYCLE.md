# 生成流的生命周期

继模型请求策略、请求上下文准备之后，将模型订阅的结束、取消和失败处理集中管理。本阶段保留原有工具轮次、提示词、正文与思考展示规则、持久化和页面操作。

## 职责

- `GenerationStream` 拥有一次模型流订阅，接收数据并返回 `completed`、`cancelled` 或 `failed`。失败保留原始异常及堆栈；数据处理回调抛错也会终止订阅，避免任务一直等待结束通知。
- `GenerationExecution.consumeStream` 将单次订阅绑定到本轮执行及指定的取消令牌，过滤停止后的数据。一次只能有一个未收尾的模型流，旧请求的延迟取消只作用于旧订阅。
- `ChatStreaming` 继续组装每轮请求、更新界面、累计正文和思考、执行工具以及保存结果；不再直接管理订阅和结束通知。

## 完成与取消

正常结束表示流已经关闭，不额外取消。主动停止或失败时发起订阅取消，并等待其异步清理完成后返回结果。`stop()` 仍立即停止界面生成状态并保存已收到内容；`stopAndWait()` 等整轮入口退出后再返回，因此替换生成不会与旧订阅清理重叠。

预算耗尽只取消当前请求，不标记用户取消，仍允许原有的一次无工具整理请求。用户停止不触发整理。整理超时、工具预算及失败重试规则保持原样。页面销毁会立即释放界面与等待者，取消的流随后自行完成清理；它不会再发布数据。

等待的是订阅的本地清理完成，不代表远端工具操作已撤销。底层流提供方需要让取消清理最终完成；不响应取消的提供方仍需在对应适配器中处理超时。

## 回归覆盖

- 延迟清理期间不接受替换生成，停止后不再接收排队数据。
- 已结束请求的延迟取消不会中断新请求。
- 提前取消不订阅数据源；提供方或数据处理回调抛错后能正常收尾。
- 取消清理异常不会成为未处理的异步异常。
- 切换到新会话再停止时，已收到正文保留在原会话，迟到数据不进入新会话，清理完成后新问题可正常生成。
- 现有任务测试继续覆盖用户停止、预算整理、整理超时、工具调用与结果重试；页面测试覆盖发送和展示。

流内容累计与界面刷新已独立为 `StreamAnswerBuffer` 和 `StreamAnswerPresenter`，见[流式答复累计与刷新](STREAM-ANSWER-PRESENTATION.md)。显示策略与订阅生命周期分别维护。
