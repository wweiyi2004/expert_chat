# 文生图、参考图与图片编辑流程

独立生图入口的提示词优化、参考图准备、媒体请求及结果转换已拆分，文生图与图生图共享这些模块。会话入口、预算、失败重试、通知和版本保存继续由控制器协调。

## 模块

- `ImagePromptOptimizer` 负责共享的提示词优化模型请求，保留原系统提示、低思考强度、正文/思考分流、120 毫秒思考进度发布及提示词清理。对话配图和独立生图的调用方各自决定何时优化及如何回退。
- `ImageReferencePreparer` 按输入顺序准备参考图。较大 Base64 数据继续通过 `compute` 解码；普通参考图复用 `ImageCodecUtil` 的尺寸限制和 PNG 文件名/MIME 转换。原版本重放只解码，不再次缩放。
- `ImageGenerationService` 共用于对话配图、独立文生图及多参考图编辑，原样传递配置、实际提示词、取消令牌和参考图顺序。HTTP 协议及端点选择仍由媒体适配器处理。
- `ImageGenerationResult` 统一附件转换及 API 修订提示词读取，附件在控制器确认未取消后才创建。原始描述、模型优化结果、实际发送提示词和 API 修订结果继续分别保留。

## 控制器保留的责任

`ChatMedia` 捕获发起会话、创建消息及重试描述、限制参考图数量、检查预算，并将图片与版本写回本轮助手消息。切换会话不会改变图片归属。

按原版本生成时，继续校验服务来源、参考图归档及哈希，恢复原模型和尺寸，使用原发送提示词、原参考图字节并建立父版本关系；不再次调用优化模型。普通发送超过参考图限制时沿用既有截取规则，版本重放无法容纳全部原图时仍拒绝执行。

## 取消与错误

参考图准备新增逐图及解码/缩放完成后的取消检查。若任务停止，放弃本次准备结果并跳过剩余参考图。解码或缩放操作本身仍会完成当前工作，但不会继续发送请求。

缺少本地数据或无效 Base64 保留原提示与图片重试操作。媒体失败后可重新执行相同的图片请求；媒体返回后若已停止，不追加图片或生成版本。成功时仍按原顺序更新消息、保存版本、保存会话和通知。

## 验证

新增模块测试覆盖多图顺序、缩放后格式、原图字节保留、大数据解码、准备阶段取消、无效参考图、优化请求与结果展示。

新增集成测试覆盖多参考图编辑及版本重放、原模型/尺寸/提示词恢复、父版本与助手消息对应、切换会话后的归属、取消后不落图、失败编辑重试。原有纯生图、对话配图、图片协议和图片缩放测试继续运行。测试使用本地替代服务，没有发送远端模型请求。
