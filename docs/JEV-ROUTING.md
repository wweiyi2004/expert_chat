# Jev 技能自动路由

在「设置 → 模型 → 预设提示词 → Jev 技能自动路由」填写 TypeSafe API Key，点击「测试 Jev 连接」，再开启路由。模型默认 `jev-latest`，最低置信度默认 60%，可调。

Jev 只负责普通聊天的技能分类，正文仍由当前聊天模型生成。故事、学习和群像模式不使用这个分类器。显式技能前缀（例如 `/代码`）优先，不调用分类接口。

## 请求和回退

- 原生接口：`POST https://api.typesafe.ai/v1/systemone`，Bearer 鉴权。协议见 [TypeSafe API](https://docs.typesafe.ai/api)。
- `Choice` 的选项来自当前启用技能的 ID、名称及「何时选用」；技能完整提示词不发送给 Jev。
- 输入仅包含本轮消息的前 8,000 个 Dart 字符单元，以及最近 4 条用户/助手消息各前 400 个字符单元。不传附件字节、项目资料或系统提示词。用户在消息中写下的内容会随消息发送。
- 关闭或密钥为空时，继续走原聊天模型分类。开启且有密钥时，总等待上限为 3 秒；低置信度、接口错误、无效响应或超出 255 个选项限制时直接使用目录的兜底技能，不再发起第二次模型分类。
- 用户停止会取消本地 HTTP 请求；不能保证远端停止处理或计费。连接测试离开页面时同样取消。
- 正常结果以 `ChatSkillSource.jev` 保存；失败仍使用原有 fallback 标记。Jev 不计入主聊天模型的 token 统计。

## 配置与密钥

非敏感参数保存于 `SharedPreferences` 的 `jevConfig`。密钥单独保存于 `flutter_secure_storage` 的 `jev_api_key`，清空输入会删除密钥。客户端不输出原始服务错误、请求体或鉴权信息。

原有「API 配置」导入导出会包含 Jev 参数与密钥，遵循该功能现有的含凭证文件规则。普通完整备份不包含 Jev 连接配置或密钥。导入旧配置文件时保留本机已有 Jev 设置。

## 验证

离线回归覆盖原生请求、前缀优先、关闭/空密钥、低置信度、错误响应、401/403/429/500、总超时、取消、设置持久化及导入导出、窄屏连接测试和主聊天回答链路。

真实中文分类评估需要用户自己的 Key。默认仅预览样例，不请求接口：

```powershell
dart run tool/jev_routing_eval.dart
# 将 TYPESAFE_API_KEY 安全地注入当前进程环境后执行：
dart run tool/jev_routing_eval.dart --live
```

实测会发送 10 条固定中文样例，产生接口用量，输出原始分类准确率、60% 阈值下的覆盖率和接受结果准确率、成功请求 P95 耗时及失败次数。小样本仅用于连通性与初步质量检查，不代表生产准确率。60% 是待实测调整的初始阈值，不能解释为正确率保证。
