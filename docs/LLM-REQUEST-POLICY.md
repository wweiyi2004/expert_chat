# 模型目录与请求策略

本次整理保留现有界面、配置格式、模型默认值和公开调用接口。模型能力、请求决策与流执行分别维护。

## 模块职责

- `lib/domain/llm/model_catalog.dart`：维护 `KnownModels`、`ModelCapabilities` 和 `ModelCatalog`。已明确登记的模型优先查询能力表；未登记名称使用原有兼容推断。模型名大小写和聚合服务商前缀统一处理，DeepSeek 服务身份判断也在这里。
- `lib/domain/llm/llm_request_policy.dart`：纯决策函数。接收本轮配置、任务类型、用户选择和循环阶段，决定实际模型、思考强度、工具权限、强制调用以及思考恢复策略。没有 Riverpod、设置存储、计时器或网络操作。
- `ChatController`：提供用户意图和配置快照，更新界面状态。`generation.dart` 提供已识别的任务类型；`streaming.dart` 执行每轮请求计划。
- `DeepSeekReasoningGuard`：保留提示词约束、流监听、计时与取消操作，按请求策略提供的阈值和重试许可执行。
- Chat Completions / Responses 适配器：保留各自协议的请求字段和响应解析，使用统一的函数工具权限检查。
- `ToolLoopPolicy`：保留对话/任务模式的循环轮数与单轮调用预算；工具轮次许可委托给请求策略。任务总预算仍由 `GenerationExecution` / `TaskBudget` 执行。

`llm_provider.dart` 继续导出模型目录中的原有类型，现有导入不需要整体迁移。

生成前的消息组装与裁剪已独立，职责及消息顺序见[请求上下文准备](REQUEST-CONTEXT-PREPARATION.md)。

## 行为约定

1. 深度思考关闭时使用当前选中模型。支持独立思考开关的模型保持当前模型；其它模型继续使用配置中的推理模型。
2. 携带图片且推理模型不支持视觉时，如果当前选中模型支持视觉、又没有单独视觉服务，则保留当前选中模型。
3. 思考强度优先使用当前手动选择，再尊重已保存的选择。没有显式选择时，DeepSeek 翻译/正文写作在非任务模式使用低强度，其它任务使用设置中的强度。
4. 强制文档修改优先；同时强制搜索与图片时使用 `required`。强制调用仅用于第一个可调用工具的模型轮次。末轮关闭函数工具。
5. 任务预算耗尽后的整理请求关闭函数工具、官方搜索和思考，并禁止嵌套的思考重试。
6. DeepSeek 首次思考上限沿用低/高/最大对应的 30/60/120 秒及 6000/12000/24000 字符。仅在无正文/工具输出时应用；最多一次关闭思考恢复，恢复阈值为 20 秒/4000 字符。测试或既有调用方提供的自定义阈值继续有效。

## 后续修改位置

- 添加明确支持的模型：更新 `ModelCatalog.entries`；DeepSeek 预设列表复用 `KnownModels.all`。不要把新模型能力判断加回页面或控制器。
- 修改任务默认思考强度：更新 `selectEffort`。任务分类本身仍属于聊天/故事流程。
- 修改每轮模型调用规则：更新 `forRound`；协议字段映射留在适配器。
- 修改思考恢复阈值：更新策略常量/`reasoningAttempt`；取消和计时实现留在保护器。

旧模型别名的能力标记在本次重构中保持原状。供应商变更后的别名同步应单独核实和测试，不能视为已被本次目录迁移修复。兼容推断也不等于供应商对能力的承诺，明确的 `LlmConfig.capabilities` 覆盖仍优先。
