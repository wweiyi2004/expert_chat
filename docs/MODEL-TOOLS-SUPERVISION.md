# 模型、工具、监督与角色积累

## 模型和账号

模型列表聚合已配置渠道。同一模型的渠道优先级与模型路由组是两种独立设置：前者不改模型；后者只有用户选择路由组并开启组内故障转移，才允许在首次响应前尝试其他模型。收到任何流式内容后、取消后、或已有工具往返历史时，不跨模型重新发送。Auto 可使用全部已配置模型或指定组，按图片和工具能力过滤；明确选择模型不会被监督建议自动替换。

明确选择的模型或组失去配置渠道时会要求重新选择，不悄悄改用全局其他模型；未显式选择和 Auto 保留已有默认策略。尚未登录、刷新授权被拒绝等渠道激活失败，与刷新网络失败分别记录；只在尚未接受响应时跳过不可用的同模型渠道，已经固定的工具任务不会借此切换主机。

显式 API Key 编辑成功写入安全存储后，才发布当前值与不含凭据的临时 profile epoch；保存失败保持旧状态，epoch 不持久化或导出。运行中的已接受渠道在完整工具轮边界读取本渠道新 key，保留 routing session 和主机，不重扫此前失败的高优先级渠道。OAuth 正常 token 刷新不会被当作用户切换账户。用户明确修改同一 profile 的地址、协议或认证方式时，应用该渠道的精确新配置；原始存储消息保留，发往新身份的临时历史另行适配。

设置中的渠道记录是本次启动实际请求的有界元数据，最多保留 200 条，界面显示最近 30 条；不记录密钥、请求或响应正文。429 可能表示限流或额度限制，402 表示服务拒绝额度，均不冒充真实剩余额度查询。

ChatGPT 采用官方 OSS 动态注册流程，由用户在系统浏览器授权，再保存官方签发的账号专用 client ID；不借用其他应用的 ID，不读其他 CLI 的凭据。API Key 与订阅分别配置。配置入口或模拟检查不等于真实账户已激活，登录后模型扫描才使用该账号的实际结果。Copilot SDK 需要应用自己的 GitHub OAuth/GitHub App 配置；没有该配置时不显示为可用的订阅渠道。Claude/Gemini 的普通 API 入口不冒充订阅 CLI 桥接。

- [Magpie 路由组与账号选择原始手册](https://github.com/yetone/magpie/blob/main/docs/reference.md#routing-groups)
- [OpenAI OSS 注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

未提供的凭据、OAuth 应用注册和实际账号授权是显式未激活条件。网站链接、预设和模拟响应均不计为订阅登录完成。

伴随连接器使用上游的 `web --gateway --addr 127.0.0.1:<管理端口> --no-open`，通过 `MAGPIE_ADDR` 固定本机 API 端口；`MAGPIE_NO_ACCOUNTS=1` 关闭自动账号发现，`DO_NOT_TRACK=1` / `MAGPIE_NO_STATS=1` 关闭遥测。配置和缓存使用应用专用 XDG 路径，发现可执行文件邻近已有 portable/data 配置会拒绝启动。用户点击才打开账号管理；私密管理令牌只留在内存并交给系统浏览器，不写入日志、导出或模型渠道。没有承诺第三方组件的 OS 凭据保险库与其他应用隔离。

端口冲突不会接管或终止已有监听器；启动成功须核验 API 与管理端口都归本次子进程所有。停止只作用于本次自持进程。真实官方 CLI `v0.1.1353` 已在 SHA256SUMS 校验后完成匿名隔离启动/端口归属/模型目录检查，结果 0 个模型，未打开管理页面、未登录、未调用付费模型。发行组件采用上游 MIT 许可，需另行安装，未把测试下载的二进制自动打包进应用。

测试文件为 [官方 Windows AMD64 CLI](https://github.com/yetone/magpie/releases/download/v0.1.1353/magpie-cli-windows-amd64.exe)，51,403,264 字节；SHA-256 `4b013a90b9f21c249bfd6dbb0dcbf0e391b8dd77ce4fd5d1b1af061308f8ac1a` 与该发行版的 [SHA256SUMS](https://github.com/yetone/magpie/releases/download/v0.1.1353/SHA256SUMS) 一致。生产用户可选择兼容的本机 CLI；启动器依赖上述 `web` 参数、XDG 路径及环境开关，未来版本不支持时会以退出/健康检查失败报告，不假定任意版本兼容。复现入口为 `tool/magpie_companion_anonymous_smoke.dart`，只对已校验的路径执行。

## 数学与工具注册表

数学工具默认关闭，设置 → 能力 → 工具注册表可开启并选择 Python 可执行文件。脚本只在第一次实际调用时加载，计算在独立进程进行；不执行模型生成的 Python、shell 或包安装命令。

内置 AST 解释器将白名单数学节点转换成 SymPy 对象，没有使用 `eval`、`sympify`、`parse_expr` 或 `lambdify` 解释模型输入。支持精确分数/根式、化简、微积分、实数解集、任意精度数值、精确统计、SVG 采样图和等式验证。输入 32 KiB，单表达式 2048 字符、256 节点、32 层；精确幂大小和输出受限。电脑本机取消会终止计算进程，超过 15 秒也会终止；手机取消先停止 HTTP 等待，远程纯计算仍可能在宿主的 15 秒界限内结束，不承诺已经远程杀进程。此限制解释器不是操作系统沙箱。

验证会保留原表达式分母、负幂及对数的非零约束，`x/x == 1` 只在 `x != 0` 条件下成立。使用默认复数主值约定，不证明任意实数定义域或连续性；无法证明返回 `equal: null`。绘图是 201 个有限采样点，不能证明没有极点。统计排序保留精确有理数精度。

用户点击安装/更新时，应用在自己的虚拟环境从官方 PyPI 安装固定 `sympy==1.14.0`，验证后才采用新可执行文件。没有模型控制的包名、下载源或命令参数；不会修改全局 Python。可停止安装，失败保留明确状态；也提供手动命令。Android/Web 通过远程任务页选定的电脑配对，使用鉴权的 `/v1/tools/math`，不伪造本地 Python；完整工具轮内的数学执行器保持同一份配对快照。电脑宿主共用相同白名单解释器、输入输出和运行时间限制，脚本只能由宿主的可信安装路径加载。

任务工具注册表区分可发现、已激活和待下一轮激活。只能申请宿主已配置、当前任务允许发现的能力，经既有权限批准后，在完整工具轮结束时加载；用户关闭或撤销的能力不能自行启用。不提供任意包执行市场。

数学工作进程使用显式环境而非继承整个宿主环境，移除远程模型配置、常见密钥/令牌/密码及代理凭据变量；远程宿主额外按已知凭据值过滤别名变量。手机的配对凭据只用于鉴权连接，不交给数学子进程。

机制依据：[SymPy 解析安全提示](https://docs.sympy.org/latest/modules/parsing.html)、[Python AST](https://docs.python.org/3/library/ast.html)。

## 可选监督

默认关闭且必须显式选择模型。默认每任务最多 3 次、间隔至少 2 个完整工具轮，仅能力缺口、重复失败、关键交付触发；最多输出 768 token，30 秒上限，关闭推理重试。只读公开目标、计划、结果摘要和产物版本，不获取隐藏思维链。

建议绑定任务和执行版本，完整结束才接受；过时建议丢弃。工具和模型必须在允许目录内，工具建议仍由现有权限执行，不能增加授权。指标区分请求、建议、交付到边界、实际采纳、拒绝、过时、无建议、失败和可用的用量。未报告用量不会显示成已知零费用。当前单元测试验证限制与无效干预，不代表已证明监督能提高所有真实任务质量。

公开上下文压缩另有独立的有界协调器，在上下文压力达到 72% 或历史数量门槛时先生成公开检查点，再由任务内存以版本比较接纳；每任务最多 2 次、至少间隔 4 个完整轮次。只接收公开正文/备注与原始目标，不接收思考或图片对象。原始目标和程序固定约束分别保留；总输入 UTF-8 字节受 12,000 与实际输入预算两者较小值限制，输出最多 1,000 token，并有真正的 30 秒等待界限与独立取消。无效或过时结果不覆盖记忆；失败后由已有本地预算策略处理，不把失败压缩称为有效工作记忆。

## 角色积累

新提案前先查询现有角色、实际工具以及资料名称索引。提案包含指令、范围、来源、模型与能力绑定，默认待验证且不进入启用库。通过普通子代理入口试用，继续受相同模型池、并发、递归和权限约束。

宿主保存试用结果/产物版本；完成声明本身不等于能力验证。设置页可审阅实际试用摘要与结果哈希，填写具体验收依据后才允许提升为复用角色。修改指令与回退创建新版本并撤销旧验收。用户可以禁用、删除、修改和回退；自动提案不覆盖已存在的用户角色。

默认仍由用户验收。可选开启独立的证据审阅模型，跟随当前模型、监督模型或显式配置模型；默认每任务最多 2 次、单次 768 token / 30 秒，同一证据不重复审阅。验收条件来自试用前已确定的任务，审阅者返回的是判定依据，不能在看到结果后自创成功条件。代码、执行、测试等角色没有宿主工具结果时不能通过；实际工具结果的有界摘录与完整证据哈希一起审阅，文本写作等输出本身是产品的角色可以审阅真实正文。截断响应、过大待审内容、已改动的证据或角色版本不自动通过。

“通过后自动加入复用库”另行显式开启，只能新增当前版本且能力/模型仍允许的角色，不自动替换已有用户角色。模型审阅和用户验收分开标注。进入复用库的角色携带来源、版本、所需工具和验收摘要；改变指令会使旧验收失效，角色路由检查所需工具是否实际可用。用户明确选择替换现有角色时，会先显示当前与候选完整指令并检查审阅期间没有新修改。

## 浏览器工作台

“人工网页”与“受控浏览器”是两个明确分开的页面。后者显示官方 Playwright MCP 的真实页面快照和截图，并可选择会话中的代理实例；没有把 WebView 宣称为同一个浏览器 DOM。

截图的视觉理解取决于实际选中模型的能力映射。Auto 在已知需要图片时筛选具备已知视觉能力的已配置模型；不强制替换明确选择的文字模型。未知模型保守地不标注视觉能力，截图不会被送给文字模型冒充已读；页面/Android 无障碍节点等文字观察仍可使用。没有根据新的模型名猜测其视觉能力。

用户接手期间，模型浏览器调用会被拒绝；接手前已派发的调用可以结束。排队但未派发的旧模型操作即使在接手结束后也会因租约版本变化而丢弃，模型必须重新观察。手动工具使用同一会话/代理实例和实际发现的参数模式，元素反馈在下一完整轮作为用户补充传入。

已检查固定版 0.0.83 实际安装包中 `playwright-core/lib/coreBundle.js` 的 `browserFactory.ts`、`idleTimer.ts` 和 `Backend.callTool` 实现：闲置计时只由 MCP 命令重置，到期调用 `browser.close()`，人工阅读/输入不延长它。因此新的预设显式使用 `--idle-timeout 0`，启动时也会规范化旧保存预设的闲置参数；不会每 5 分钟静默丢弃人工页面。需要释放时，用户接手后可选择实际已发现的 `browser_close` 关闭当前代理浏览器；停止任务、删除会话及正常客户端销毁负责关闭隔离服务。没有长期保存未关闭浏览器状态或强制进程崩溃后恢复页面的承诺。

实际固定版 `@playwright/mcp@0.0.83` 本地合成页面验证脚本：`dart run tool/playwright_workbench_smoke.dart`。检查真实 `target` 模式、导航后快照、手动输入/点击、截图、接手后新观察和不同代理隔离。脚本不读取用户浏览器或账号。
