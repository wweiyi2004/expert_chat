# 数据可靠性与原生验证

## 本次改动的边界

- 会话读取失败保持 `messagesLoaded = false`。重命名等元数据写入不删除已有消息；文字、生图、后台文档任务和共享生成入口拒绝使用未加载的会话。
- 错误栏的重试操作仅重新读取会话，不发起模型请求。读取与待提交写入按同一队列排序，读取期间的新标题等元数据保持有效。
- `GenerationExecution` 独立管理一次生成的接受状态、取消、流订阅、结束等待和跨模型轮次的任务预算。停止请求后，直到入口的异步清理结束才接受下一次生成。
- `ToolCallRunner` 独立执行工具批次，统一限制单轮/整轮调用数，并为被跳过的调用返回对应的工具响应。具体搜索、图片、文档适配器及 UI 更新仍由控制器提供；这次没有重写所有提示词组装或页面。
- 业务数据结构仍为 v16；没有新增数据库迁移或改变备份格式。新增依赖只用于 Flutter 原生集成测试。

## 自动化检查

```sh
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
flutter test integration_test/reliability_smoke_test.dart -d windows --reporter expanded
flutter build apk --debug --target-platform android-arm64 --no-pub
```

`test/chat_history_recovery_test.dart` 使用真实的内存 SQLite，注入读取失败，检查重命名、生成拦截、重试恢复及读取期间的标题修改。`test/generation_execution_test.dart` 检查重复提交、取消后等待、预算耗尽、工具中断和异常清理。

`integration_test/reliability_smoke_test.dart` 在原生应用进程内使用真实的文件 SQLite、素材文件、Markdown 记忆、`.ecbackup` 和恢复日志，执行以下断言：

1. v15 磁盘数据库升级至当前版本后，原消息保留。
2. 生成尚未结束时，回复检查点已经写入磁盘；销毁控制器并重新打开数据库后，原消息和检查点仍在，模型请求不自动重放。
3. 将备份写入文件、重新打开数据库并导入后，原会话保留，新增一份副本；原素材和副本的字节一致。
4. 模拟 SQL 未提交时留下的恢复日志，重启恢复服务后回滚记忆/设置，删除未引用的暂存文件，保留已提交会话。
5. 恢复的历史能够在原生聊天页面渲染，且没有自动进入生成状态。

测试在系统临时目录中创建独立沙盒，并重定向路径服务与偏好设置，使用模拟模型，不调用真实 API。中断通过销毁控制器和重开数据库模拟，不能代替操作系统强制结束进程的设备测试。

`.github/workflows/native-validation.yaml` 在推送、PR 或手动触发时执行 Android 调试构建、iOS 无签名构建、Windows 原生集成测试。调试/无签名产物仅用于验证，不能作为正式发布包。

## 设备发布验证

在专用测试设备或模拟器上执行，先保留测试数据和旧版安装包。不要卸载应用来代替升级；卸载会改变数据保留条件。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 覆盖安装升级 | 旧版创建含分支的会话、素材和记忆，用同签名新版覆盖安装 | 原会话、消息数、所选分支和素材字节保持一致；正常进入聊天 |
| 后台后完成 | 生成中切至后台，再返回前台 | 原会话接收结果，无重复回复或跨会话写入 |
| 系统结束进程 | 已确认检查点写入后，从系统结束应用，再启动 | 已完成历史和最近持久化检查点仍在；普通模型/工具请求不自动重放 |
| 离线恢复 | 导出备份，断网，导入副本并重启 | 本地会话与素材可读，原数据保留；远程链接不被误报为已下载 |
| 恢复被中断 | 在测试构建的恢复阶段结束进程，再启动 | 根据 SQL 提交标记完成清理或回滚，无半导入会话和重复自动任务 |

普通流式回复的检查点按已有 3 秒/8,192 字符阈值触发，磁盘写入为异步操作。进程结束测试应以“最近已写入检查点”为验收基准，不能要求尚未落盘的最后一个字符必定恢复。
