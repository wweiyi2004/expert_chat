# 流式答复累计与刷新

在请求准备和订阅生命周期拆分之后，将正文、思考文本、思考计时及界面刷新从 `ChatStreaming` 中独立。模型调用、工具执行、预算控制、引用与活动记录仍在原流程中。

## 模块边界

- `StreamAnswerBuffer` 累计一条答复的正文与思考文本。思考计时跨工具轮次累计，正文开始或一轮思考结束时冻结；本地任务提示不启动计时。替换正文和思考文本用于清除工具前的过渡话语及保留原有的错位答复恢复行为。
- `StreamAnswerPresenter` 使用现有 `DualStreamUiCoalescer` 管理两块内容的独立刷新节奏，发布不可变的 `StreamAnswerSnapshot`。控制器通过回调更新指定会话的助手消息，并执行保存检查点。
- `StreamUiCoalescer` 保持原有首帧、短答复、长答复、缓存命中和用户阅读位置对应的批量刷新策略。
- `GenerationStream` 继续只管理模型订阅生命周期，不承担内容显示策略。

## 保持的行为

1. 通常只发布用户当前阅读的内容区域，另一块保留上次已发布的文本。切换阅读位置会主动刷新；离开两块内容时使用原有的 3 秒间隔刷新。
2. 长思考之后，正文使用自己的短答复刷新节奏。如果已有较慢的思考定时器，正文可以将等待时间缩短。
3. 模型一轮结束、插入服务端工具活动、清除工具前的过渡正文和停止生成时，仍强制发布全部累计文本。
4. 保存检查点在发布快照后触发，沿用 3 秒或新增 8192 字符的阈值。它是尽力保存，最终完成时仍由控制器等待正式持久化。当前只显示一块内容时，检查点保存的是已发布的会话状态；停止前的全量刷新会补齐另一块文本。
5. 销毁只取消刷新定时器，不再发布快照。控制器保持先刷新再保存/停止的顺序，销毁后的迟到数据不会触发刷新。

## 验证

`stream_answer_presenter_test.dart` 使用可控制的计时验证跨轮次思考时长、首帧、阅读位置切换、长思考后的正文、离开时的刷新、停止后的完整快照、销毁、保存阈值和文本替换。原有页面、工具任务、答复恢复及流合并测试继续验证控制器接入。

本次没有修改供应商提示词、思考强度、工具预算、模型参数或存储格式，也未进行远端模型实测。
