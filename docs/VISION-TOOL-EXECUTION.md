# 识图工具执行

模型调用 `analyze_image` 和生成前的自动识图现在共用 `VisionToolExecutor`。控制器提供配置快照、预算检查和活动发布回调，并将返回的异常转换为限定于对应会话的错误提示。

## 职责与行为

- `VisionTools.attachmentsFor` 收集活动分支上的用户图片，按附件 ID 去重，排除助手生成的图片。参数别名、默认问题、按文件名忽略大小写匹配及省略文件名时选择最后一张图片的规则保持原样。
- `VisionToolExecutor.execute` 处理未配置服务、缺少附件、工具参数和图片选择，并保留工具回复的图片名称前缀。
- `VisionToolExecutor.analyze` 构建原有系统提示及单张图片请求，累计非空正文增量并去掉结果首尾空白。它不把视觉模型的思考增量当作观察结果，也不改变模型参数。
- 工具调用的次数仍由 `ToolCallRunner` 扣减；预识图通过控制器回调检查并扣减预算。服务先发布开始活动，再检查预算，与原有时序一致。配置或附件无效时不会访问提供方或扣减预算。
- 活动 ID、开始/结束状态、空结果、失败和取消提示保持原样。工具结果保存、失败步骤重试、会话归属及后续模型请求仍由原有执行流程处理。

## 取消边界

请求继续传入同一个取消令牌，读取增量前检查是否已取消。抛出取消异常时记录失败活动并返回取消提示，不设置新的会话错误。

保留现有兼容行为：如果取消没有抛异常，而是增量检查发现已取消，则忽略后续内容并保留已收到的文本；有文本时该活动仍记为完成。此次没有改写底层视觉流的取消机制或状态语义。

## 验证

`vision_tool_executor_test.dart` 覆盖实际请求提示词与图片载荷、指定和默认图片、无效输入、预算拒绝、空结果、失败重试、取消异常、迟到内容及活动分支隔离。

控制器集成测试验证识图使用独立视觉配置、工具协议回复保留调用 ID、识图活动与结果保存到原助手消息。既有图像发送、模型工具暴露、任务预算和页面测试继续运行。测试不调用远端视觉服务。

生图、图片编辑及文档工具未包含在此次拆分中。
