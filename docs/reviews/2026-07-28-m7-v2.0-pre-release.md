## Summary

M7’s **security skeleton is largely in place and matches the product rules**:

- SSH secrets (password / private key PEM / passphrase) go only to `flutter_secure_storage` via `ResearchSecureKeys`; `SshProfile` / `ResearchPrefs` JSON in SharedPreferences is non-secret.
- No `print` / `debugPrint` of credentials in the research path; connect errors go through `_safeError` + transcript redaction.
- `CommandProposal` cannot be passed to the shell writer; only `ApprovedCommand` + `ApprovedCommandExecutor` write, and only after UI double-confirm (`确认执行` → final sheet). No “总是允许” / “自动执行” strings in UI sources (asserted by tests).
- Approval binds `hostId + connectionGeneration`; executor rejects mismatch; proposal cleared after execute / disconnect.
- Ctrl+C block defaults **on**; `TerminalInputGuard` strips `0x03`; hardware path uses `terminal.onOutput` → `writeUserInput`; forced interrupt requires explicit confirm.
- Web: settings switch disabled (`kIsWeb`), controller short-circuits connect, conditional export `research_ssh_client.dart` → stub without `dart:io`.
- Shell uses fixed `IndexedStack` order so enabling research does not recreate Studio/Settings; terminal page mounts only when research is on; disable path calls `releaseAll()` and falls back from terminal tab.

**Not release-clean for a v2.0.0 label yet.** There are concrete correctness bugs (async AI apply across host/generation, UTF-8 shell write encoding, connect/disconnect races, remote drop not reflected in UI), the app version is still 1.6.3, and several PROJECT_PLAN M7.8 acceptance items remain device-unverified. Domain unit tests are strong; **no widget layout tests** for the terminal page.

**Verdict**: Ship as **experimental / internal** after fixing Issues 1–3 (and preferably 4). Do **not** market as finished v2.0.0 research mode until those land + real SSH/tmux smoke on Android/Windows.

## Issues

### Issue 1 -- Severity: bug
- File: `lib/state/research_terminal_controller.dart:500-560`
- Description: `analyzeWithAi` does not snapshot `connectionGeneration` / `activeProfileId` before the LLM await. After the stream finishes it only checks `_disposed`, then writes `proposal` into current state. Sequence: analyze on host A → user disconnects and connects host B (generation bumps, proposal cleared on connect) → in-flight analyze completes → **stale proposal from host A context is attached to host B**. UI still offers `确认执行`; `approveCurrentProposal` will mint an `ApprovedCommand` for the **new** host/generation. Local risk re-check helps, but the command was designed for another machine’s transcript.
- Suggestion: At start of analyze, capture `gen` + `hostId`. After await, if `_disposed || !ref.mounted || state.connectionGeneration != gen || state.activeProfileId != hostId`, drop the result (set `analyzing: false` only if still same request). Optionally cancel via `CancelToken` on disconnect.
- Status: open

### Issue 2 -- Severity: bug
- File: `lib/domain/research/research_copilot_service.dart:77-80`
- Description: `ApprovedCommandExecutor.execute` sends `payload.codeUnits` (UTF-16 code units) to `writeToShell`, while interactive keyboard path correctly uses `utf8.encode` (`research_terminal_controller.dart:249`). `ResearchSshClientIo.write` treats the list as raw bytes (`Uint8List.fromList`). Non-ASCII commands (common in lab paths / Chinese filenames) will be truncated/garbled (e.g. U+4E2D → low byte only). Tests only cover `echo hi`.
- Suggestion: `writeToShell(utf8.encode(payload));` and add a unit test with a non-ASCII command asserting byte equality to `utf8.encode(...)`.
- Status: open

### Issue 3 -- Severity: bug
- File: `lib/state/research_terminal_controller.dart:260-374` (with `disconnect` at `:388-409`)
- Description: `connect` assigns `_client = client`, then `await client.connect` / `await saveProfile` without a generation or client-identity token. If the user disconnects (or starts another connect) during those awaits, `disconnect` nulls `_client` and sets disconnected; the original `connect` continuation can still attach stdout/stderr subscriptions, set `terminal.onOutput`, and mark `status: connected` against a client that was already disconnected—or fight a newer connection. No `if (!identical(_client, client)) return;` guard after awaits.
- Suggestion: Keep a local `client` reference and after every await require `identical(_client, client) && !_disposed && ref.mounted` before mutating state/subscriptions; on mismatch, ensure the local client is disconnected and exit.
- Status: open

### Issue 4 -- Severity: bug
- File: `lib/domain/research/research_ssh_client_io.dart:188-198` (controller never listens to `done`)
- Description: When the remote shell closes, Io client sets `_connected = false` and completes `done`, but `ResearchTerminalController` never subscribes to `client.done`. UI can remain `ResearchConnectionStatus.connected` with a live-looking `TerminalView` while writes no-op. Stale “已连接” also weakens operator trust for long training observation.
- Suggestion: On successful connect, subscribe to `client.done` and call `disconnect(bumpGeneration: true)` (or a dedicated `onRemoteClosed` path) with mounted/`_disposed` guards; surface a clear status message (“远端 shell 已关闭”).
- Status: open

### Issue 5 -- Severity: suggestion
- File: `lib/features/research/research_terminal_page.dart:1215-1277` (`cwdHint: 'cwd'`, copy “当前 shell cwd（未探测）”)
- Description: Product plan requires final approval to show working directory. UI is honest that cwd is not probed, but approval still records a placeholder `cwdHint`. Operators can misread impact of relative paths.
- Suggestion: Best-effort `runExec('pwd -P')` (or parse OSC 7 if available) before final confirm; if unknown, keep explicit “未知” and disable relative-path comfort text.
- Status: open

### Issue 6 -- Severity: suggestion
- File: `lib/state/research_terminal_controller.dart:161-207` + `lib/features/research/research_terminal_page.dart:1142-1177`
- Description: Changing `authType` (password ↔ privateKey) passes only the new secret fields; the other secure keys are not deleted. Orphan password/key/passphrase can remain in secure storage for that profile id (not in SharedPreferences, but residual secret surface / wrong-cred confusion on later auth flips).
- Suggestion: On authType change, delete unused `ResearchSecureKeys.*` for that profile; document empty-field “keep previous” only for the active auth method.
- Status: open

### Issue 7 -- Severity: suggestion
- File: `lib/state/research_terminal_controller.dart:388-409`, `500-560`
- Description: `disconnect` / `releaseAll` clear `proposal` but do not clear `analyzing: true`. An in-flight analyze keeps the spinner semantics until completion, then may re-set proposal (see Issue 1). Minor UX inconsistency on disable-research / disconnect during AI.
- Suggestion: `copyWith(analyzing: false, proposal: null)` on disconnect; pair with Issue 1’s generation guard.
- Status: open

### Issue 8 -- Severity: suggestion
- File: `test/research_mode_test.dart` (entire file; static gates ~`:690-715`)
- Description: Domain/controller tests are solid (guard, risk, transcript redaction, approval generation, prefs secrets, shell tab visibility). M7-E asked for phone layout widget tests to catch Sheet/nav overflow; there is only a source-string structural check, no `pumpWidget` of `ResearchTerminalPage` / narrow width.
- Suggestion: Add golden or smoke widget tests: narrow width + connected fake state (tmux bar + shortcut bar + FAB), AI sheet open, connection manager sheet—assert no overflow exceptions.
- Status: open

### Issue 9 -- Severity: suggestion
- File: `lib/domain/research/command_risk.dart:84-90` + executor path
- Description: Destructive patterns such as `rm -rf` are classified **high**, not **blocked**. After two confirms they still execute. May be intentional for power users; for v2.0 “safe default” messaging, high≠blocked can surprise.
- Suggestion: Either document clearly in UI (“高风险仍可确认执行”) or promote a denylist subset to `blocked` (e.g. `rm -rf /`, raw disk `dd`, `mkfs`) that cannot enable the final button.
- Status: open

### Issue 10 -- Severity: nit
- File: `pubspec.yaml:19`
- Description: Tree still declares `version: 1.6.3+10` while this review targets a **v2.0.0** research-mode release narrative. Shipping artifacts under 1.6.3 while calling the train 2.0.0 will break update/OTA expectations and support comms.
- Suggestion: Version bump + changelog only when M7 blockers above are fixed and smoke-verified; until then call builds “1.7-m7-preview” or similar.
- Status: open

### Issue 11 -- Severity: nit
- File: `lib/domain/research/tmux_service.dart:77-120` + controller `currentTmuxName`
- Description: `currentTmuxName` is set optimistically after writing attach/switch bytes; there is no confirmation from remote. Failed attach leaves UI believing it is inside tmux, so later `switchOrAttachInShell(currentlyInTmux: true)` may send `switch-client` into a bare shell.
- Suggestion: Parse mild heuristics from transcript, or run `echo $TMUX` via exec when not in interactive critical path; on detach/attach failure clear `currentTmuxName`.
- Status: open

### Issue 12 -- Severity: nit
- File: `lib/features/research/research_terminal_page.dart:432-444`
- Description: Terminal font lists `Cascadia Mono` first; it is not bundled in `pubspec` assets (only NotoSansSC). Harmless fallback to Consolas/monospace, but first-run metrics may differ per OS.
- Suggestion: Use a bundled monospace or document platform font dependency.
- Status: open

## What looks good (do not regress)

- Host key trust / mismatch dialogs; default deny if handlers missing; fingerprint is dartssh2 OpenSSH-style `SHA256:…` UTF-8 bytes (decode is correct).
- Transcript ring buffer limits + ANSI strip + secret redaction before AI.
- Local risk floor `max(model, local)` on parse and on edit.
- tmux session name charset validation + `shellSingleQuote` for create/attach.
- Research mode off: confirm if session active → `releaseAll` → hide tab; web cannot enable.
- Rainbow FX is overlay-only; does not affect SSH state.
