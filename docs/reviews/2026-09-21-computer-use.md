# Windows Computer Use 验证记录

日期：2026-09-21。实现与协议参考 DeepSeek Harness 官方 Cua Driver 接入。使用官方下载的 Cua Driver 0.28.0 Windows x64，ZIP SHA-256 为 `9db2096df8d80da4e73ffb797947dcdfab2a362faddd9d1b77682c77aace5aa9`，已校验。

## 完成内容

- 本地 stdio MCP：直接启动可执行程序，协议初始化、工具分页、连接复用、关闭、超时与取消；进程退出后不重放动作。
- 配置界面：本地程序路径、参数、工作目录、Cua 预设及前台许可。导入本地配置默认关闭。
- 桌面执行：仅任务模式与已选服务可调用，有限工具集，后台优先，准确窗口与近期观察约束，每个动作后重新观察。
- 图片与定位：工具截图传入下一轮，旧工具截图退出模型上下文；当前 snapshot_id 与 element_token 传给模型。

## 实机驱动验证

通过本项目 McpClient 连接 `cua-driver.exe mcp --direct`：发现 57 个上游工具；权限查询确认普通用户完整性级别下 UIA 可用、PostMessage 可用。应用只暴露策略允许的子集。

在独立的 `build/computer-use-smoke/expert-chat-cua-test.txt` 测试文档上，通过真实记事本 UIA 写入带时间戳的新内容。临时测试窗口占据前台，记事本位于后台。验证结果：

| 检查 | 结果 |
|---|---|
| 测试开始时记事本在后台 | 通过 |
| UIA 设置文本并从新控件树回读 | 通过 |
| 保存后的磁盘内容包含本次唯一文本 | 通过 |
| 写入期间前台窗口与鼠标位置保持不变 | 通过 |
| 完整保存流程结束后前台窗口与鼠标位置保持不变 | 通过 |

新版记事本拒绝后台 Ctrl+S：驱动报告快捷键对应的 UIA 操作不在当前控件树中。测试重新观察，找到“文件”菜单并展开，再基于新观察点击“保存”，成功落盘。没有切换至前台重试快捷键。

实机报告保存在 `build/computer-use-smoke/result.json`。焦点与鼠标检查比较动作前后状态，不是全程高频监控；不能据此宣称任何时刻绝无瞬时变化。未测试微信等其他应用的后台能力，也未进行真实模型驱动的开放式桌面任务。

## 使用入口与限制

详见 [配置说明](../COMPUTER-USE.md)。此版本是当前 Windows 桌面的后台优先操作，不是虚拟机或独立虚拟桌面。停止不会撤销已经发生的操作。中断后需新一轮任务重新观察，不自动恢复并重放旧动作。
